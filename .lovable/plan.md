## Goal\nMake Run Sequence behave like an autonomous worker: it should consume the context already attached in the Run Sequence dialog, choose the best matching attached checklist by loose reference when needed, and never pause to ask the user for more context mid-run.\n\n## Plan\n\n### 1. Fix the context handoff so attached checklist text reaches the actual execution step\n- Keep the existing global context attachments from the Run Sequence dialog.\n- In the sequence worker, resolve the attached checklist text into a per-line execution context before dispatching the child job.\n- Pass that resolved text context into the child job payload so the actual tool call uses it, not just the planner.\n- Ensure text, search, image, and video jobs all inherit the resolved context block when they are launched from Run Sequence.\n\n### 2. Add deterministic loose matching for attached checklist context\n- Add a per-line context resolver that scores attached checklists against the current line using loose title/token matching.\n- Support natural references like “this checklist,” “attached checklist,” partial titles, and close title matches instead of requiring exact names.\n- If only one text checklist is attached and the line asks to use attached context, automatically select it.\n- When the line clearly points to one attached checklist, use that checklist as the primary text context for that step.\n- When the line is generic, fall back to all attached text context in a bounded, ordered way.\n\n### 3. Change the planner from “assistant” behavior to “executor” behavior\n- Update the planner instructions so it treats `linked_context_text` as already-approved working context, not something to ask the user to provide.\n- Explicitly forbid conversational replies like “please provide context.”\n- Require it to either:\n  - pick a tool/action using the available attached context, or\n  - return `no_action` only for truly non-actionable lines or impossible missing required media.\n- Preserve the strict per-line execution model and one-line-at-a-time behavior already added.\n\n### 4. Improve failure handling so the run keeps moving instead of stalling\n- If a line references context loosely and a best match exists, use it instead of treating it as missing.\n- If no checklist match is strong enough, record a clear skip reason internally and continue to the next line.\n- Make skip/error messaging operational and non-conversational so the queue never looks like it is waiting for a reply.\n\n### 5. Add visibility so you can verify what context the line actually used\n- Add lightweight run metadata for each line showing which attached checklist(s) were selected as context.\n- Surface that in the Action Queue or line output so you can confirm the agent used the intended attached context.\n- Keep it compact: enough to debug context selection without cluttering the checklist.\n\n### 6. Validate against the exact failure modes you described\nTest these scenarios after implementation:\n- A line says “use the information on this checklist…” with one attached checklist.\n- A line references an attached checklist with a loose/partial title.\n- A line uses generic wording and multiple attached checklists are present.\n- A line needs attached text context plus attached media.\n- A run is queued and completes step-by-step without any conversational “please provide context” output.\n\n## Technical details\n- No schema change is required for the core fix.\n- Main files likely to change:\n  - `supabase/functions/process-action-queue/index.ts`\n  - `supabase/functions/plan-action-sequence/index.ts`\n  - `src/pages/ActionQueue.tsx` and/or related queue UI for context visibility\n- Highest-probability root cause:\n  1. Attached checklist text currently reaches the planner, but not the dispatched child execution jobs.\n  2. The planner prompt does not strongly tell the model that attached text context is already available and must be used.\n  3. There is no deterministic loose-match resolver for attached checklist references, so the model sees a text blob instead of a selected source.\n\n## Success
